# Translations

| Locale | URL | File | Published |
| --- | --- | --- | --- |
| English (default) | `/` | `src/i18n/en.json` | yes |
| Indonesian | `/id/` | `src/i18n/id.json` | no (switched off) |

## Turning a language on or off

Edit `LANGUAGES` in `src/config.ts`, then rebuild:

```ts
export const LANGUAGES: Record<Locale, boolean> = {
    en: true,
    id: false, // true publishes /id/
};
```

When a language is off:

- its page is not built
- the language switcher leaves it out, and hides itself when only one language is left
- `hreflang`, `og:locale:alternate` and the sitemap leave it out
- its URLs (`/id`, `/id/...`) redirect to `/` with a 302: `dist/_redirects` on Cloudflare, Astro's `redirects` in `astro dev`

Its JSON file stays in the repo and is still type-checked, so switching it back on needs no other change. The default language (`DEFAULT_LOCALE`) must stay on.

Language routing is done by the pages, not Astro's i18n routing: `src/pages/index.astro` is the default language, and `src/pages/[locale]/index.astro` generates one page per other published language.

## Editing text

All visible text is in the locale JSON files, grouped by scene:

```text
meta      title, description, social description, image alt, job title, bio
chrome    language switcher, pager and scroll hint
home      intro scene
code, play, contact, wallet   one group per scene
notFound  404 page
```

Each scene group has:

- `nav`: the pager label.
- `label`: the small label above the title.
- `ghost`: the large outlined word in the background.
- `title`, written as `{ "lead": "...", "accent": "..." }`. `accent` is drawn with the gradient. `lead` keeps its trailing space.

Do not hardcode visible text in a component.

## Missing translations fail the check

`en.json` is the reference. In `src/i18n/ui.ts`, `Dict` is `typeof en` and every locale is assigned to `Record<Locale, Dict>`. If `id.json` lacks a key that `en.json` has, `npm run check` fails and names the key.

When adding text, add the key to `en.json` first, then to `id.json`.

## Text used by JavaScript

`home.js` contains no language strings. It reads them from the markup:

- Pager button labels: `aria-label` is `nav.pager[data-go]` followed by the scene's `data-title`.
- Copy button: the original text is the button's own text, and the "copied" text is `data-done`.

Keep it this way when adding UI that JavaScript changes.

## Adding a language

1. Create `src/i18n/<locale>.json` with the same keys as `en.json`.
2. In `src/config.ts`, add it to `LOCALES` and to `LANGUAGES`.
3. In `src/i18n/ui.ts`, import the JSON and add it to `dicts`, `localeNames`, `htmlLang` and `ogLocale`.
4. If the language needs characters outside Latin, add a font subset that covers them. The self-hosted JetBrains Mono is Latin only.

The page, switcher entry, `hreflang` tags, sitemap entry and redirects all follow automatically.
