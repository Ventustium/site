# SEO and link previews

`src/layouts/Base.astro` builds the whole `<head>` for each locale from the locale JSON (`meta` group) and `src/data/site.ts`.

## Per page

| Output | Source |
| --- | --- |
| `<title>`, meta description | `meta.title`, `meta.description` |
| canonical | the page's own URL (`https://ventustium.com/`, or `/id/` when Indonesian is on) |
| `hreflang` alternates | one per published language plus `x-default` → `/`, only when more than one language is published |
| Open Graph / Twitter card | `meta.socialDescription`, `meta.ogImageAlt`, `og:locale` per language |
| JSON-LD | `Person`, `WebSite` and `ProfilePage` (see below) |

Link previews on Discord, WhatsApp, Telegram and X use `public/assets/image/og.jpg` (1200×630, opaque background) with `summary_large_image`. `theme-color` (`#7b4dff`) also sets the colour of the Discord embed bar.

## Structured data

- `Person`: name, alternate names, email, `jobTitle` and `description` from `meta`, `knowsAbout` from `stack`, and `sameAs` with every profile link.
- `WebSite`: lists every published language in `inLanguage`.
- `ProfilePage`: one per published language, with `dateModified` set to `UPDATED`.

## Crawler files

| File | Purpose |
| --- | --- |
| `sitemap.xml` | generated by `src/pages/sitemap.xml.ts`: every published language, `<lastmod>` from `UPDATED`, `xhtml:link` alternates when there is more than one |
| `robots.txt` (`public/`) | allows everything and points to the sitemap |
| `llms.txt` (`public/`) | plain-text profile summary for AI assistants |

## When content changes

1. Bump `UPDATED` in `src/data/site.ts`. The JSON-LD and the sitemap pick it up.
2. Update `public/llms.txt` if facts or links changed.
3. If you replace `og.jpg`, give it a new filename and update `Base.astro`. Platforms cache preview images aggressively.

## 404 page

`src/pages/404.astro` is one file that shows every published language. It passes `noindex` to `Base.astro`, which drops the canonical URL, the alternates and the JSON-LD.
